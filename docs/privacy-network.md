# Privacy: every outside address

Written 2026-11-05 for rule 6 of `docs/05-public-release.md` ("nothing phoning home"), brought up to date on 2026-11-06 after the audit against the seven tenets (CONTRACT.md section 0: privacy by default, no data sent to any company by default, local where possible, security by default, cohesion, easily modded, wanting to help people). An outside address is anything that is not the hub machine, the owner's own devices, or the owner's own machines on their tailnet or home network.

The rule: nothing outside is contacted until a module or a setting the owner turned on needs it, and where that sends something to a company, the place where it is turned on says what goes and to whom. The lists below are every outside address the hub, the web app (browser, home screen app and the Windows app) and the Apple apps can contact, what causes it and what is sent. `hub/test/no-phone-home.test.ts` fails when the shipped code names an outside host this page does not list.

## A new hub with nothing set up

- **Hub:** contacts no outside address apart from how devices reach it: with Direct link, the installer's default, it keeps one connection to n0's relay (see the table). At start it reads its own files, asks the local Tailscale daemon for the tailnet name (`tailscale status --json`, nothing leaves the machine), reconciles the notes folder and starts its timers. Every timer checks its module and its setting before it contacts anything, so with no model chosen, no sign-ins, no monitors, no machines added and no backup host there is nothing to contact. Web lookups start off (since 2026-11-06), so no question reaches a search engine until the owner turns them on. Setup's model search asks only this machine: `127.0.0.1` ports 11434, 1234, 8080, 8000 and 1337, plus `172.17.0.1:11434` and `host.docker.internal:11434` when the hub runs in a container. No model and no time zone are assumed: the Welcome page picks the model, and the hub uses the machine's own time zone.
- **Web app:** contacts the hub only. Two browser features that would reach a company are behind a module and a notice: dictation (Voice) and location (Calculators); see "Web app".
- **Apple apps:** contact the hub only. Dictation stays on the device where it can; see "Apple apps".

On the home network only, not an outside address: with Home Wi-Fi only chosen, the hub announces itself over Bonjour (`_aeneas._tcp`, hub/src/announce.ts) so paired devices find it again after the router gives it a new address. The announcement holds the hub's port and its certificate's SHA-256 (which any device on the network sees by connecting anyway) under the name "Aeneas hub" and a few characters of that fingerprint, never the computer's or the owner's name. Devices still accept the hub only when it presents the certificate pinned from the QR code. Direct link and Tailscale do not announce.

Tailscale in Aeneas (iPhone, iPad and Mac, off until the person taps Sign in to Tailscale here on a Tailscale hub): the app runs Tailscale's own library (TailscaleKit, BSD-3-Clause) for its own requests only. It talks to Tailscale's coordination server (`controlplane.tailscale.com`), the sign-in page (`login.tailscale.com`, in a browser sheet: Aeneas never sees the password) and Tailscale's relays, and Tailscale learns what its own app would tell it: the account, the device's name ("aeneas-" and the device name) and when it is online. Tailscale's log is not written anywhere. Signing out tells Tailscale and removes the device's Tailscale key.

Kept on the hub, and for how long: chats and host command output are kept until the owner sets a number of days (`/settings/retention`; the Welcome page of a new hub offers 90 days for chats and 30 for command output; a hub with no setting deletes nothing). Logs hold route patterns, status codes and durations, never query strings, titles or personal text. Unauthenticated callers learn only that the hub answers (`/health` says `{ ok: true }`), and `/privacy`, which names the owner, answers only while a Google app is set up or a mailbox is linked.

## Web app

The web app talks to one address: the hub the owner set in Setup. It loads its own files from the hub (`/app`) or from inside the Windows app. The service worker caches only those files. There are no web fonts, CDNs, analytics, crash reporting, link previews or favicons from other sites, and the update check is a look at the hub's own `/app` files. `/app` is served with a Content-Security-Policy that allows only the hub itself (`APP_CSP` in `hub/src/app.ts`), and the Windows app sets the same policy in `tauri.conf.json`, so a script slipped into a note or a page has nowhere to send what it reads. Other web pages open in the same browser get no CORS answers from the hub, so they cannot read its replies.

- **Dictation (Talk).** It is the browser's own speech recognition: Chrome sends the audio to Google, Edge to Microsoft, Safari to Apple. The button shows only while the Voice module is on, and the first time it says which company hears the audio, before it listens.
- **Read aloud.** Replies are read only with a voice that runs on the device (`localService`); with none, nothing is read aloud. Online voices (Google's and Microsoft's) are never used.
- **Location (Calculators, the bill splitter's meals tax).** Asked only when the owner taps Use my location. The browser finds the position, and Chrome, Edge and the Windows app (WebView2) ask Google's or Microsoft's location service to do it; the module's note says so. The hub then finds the state from the position, rounded to about a kilometre, with its own state outlines.
- **Pictures.** Gallery and assistant pictures, Steam game pictures and wiki pictures kept on the hub are fetched from the hub with the device's key in the header. A picture in a note, the journal, a wiki page or a model's reply that points to another site is shown as a link, "A picture, not loaded until you open it".
- **A removed device.** When the hub says this device was removed, the web app deletes its key and its whole offline copy (IndexedDB) before it shows "This device was removed".
- **Links opened only when tapped**, each in a new tab with `rel="noreferrer"` so the page is not told where the link was: `maps.apple.com` with a person's address, `ollama.com/download`, `steamcommunity.com/dev/apikey`, `developer.atlassian.com/console/myapps`, `console.cloud.google.com/auth/clients`, Letterboxd film pages, renewal pages, job postings, Confluence pages, `mail.google.com` record links, and links inside notes, wiki pages and replies. `takeout.google.com` is named in the import help as text, not a link.
- **Windows app (Tauri).** It runs in Microsoft's WebView2. The installer downloads the WebView2 bootstrapper from Microsoft only when WebView2 is missing (it ships with Windows 11 and comes with Windows 10's updates). WebView2 updates itself through Microsoft's updater and follows Windows' diagnostic data setting; the project cannot turn that off. The app has no update check and no updater plugin. `schema.tauri.app` in `tauri.conf.json` is the schema editors read, never contacted by the app.
- **The browser's own features** (Safe Browsing in Chrome, Fraudulent Website Warning or iCloud Private Relay in Safari) are the browser's settings, not the app's.

## Apple apps (iPhone, iPad, Mac, Watch)

The apps' own requests go to the hub, over HTTPS: a hub address typed without a scheme is taken as `https://`. The Watch makes no HTTP requests: it relays through the iPhone over WatchConnectivity, which Apple may carry through its own relay when the two are apart. There are no third-party packages or SDKs, no analytics, no crash reporter, no push notifications, no iCloud or CloudKit, and no associated domains.

| Contact | Caused by | What is sent | Notes |
|---|---|---|---|
| Apple's speech servers | Dictation in Capture and the Assistant (`Dictation.swift`), with the Voice module on | Live microphone audio, only when the device cannot recognize the language on the device | Before the first use that would go to Apple, the app says so and asks. On the Watch, the system's dictation decides, and the app says so before the first use there too |
| iCloud Backup | The device's own backup setting | Nothing of the app's by default: the local copy of the owner's data (`store.sqlite` and the caches) is excluded from iCloud Backup, since it refills from the hub. Settings, Privacy has "Include in iCloud Backup" (off) | Since 2026-11-06 |
| Spotlight, widgets and the lock screen | Settings, Privacy: "Show in Spotlight" (titles only, never note text) and "Lock screen shows titles"; both chosen in setup, off by default | Nothing leaves the device; these decide what other people can see on it. Lock screen widgets and the Live Activity mark titles as private (`.privacySensitive()`) | Since 2026-11-06 |
| The owner's own accounts behind Apple Reminders, Calendar, Contacts, Health and Photos (iCloud, Google, Exchange) | Each module's own switch and the permission it asks for | What the app writes into those stores, carried by the operating system's own sync | Built as designed |
| Location | Calculators, Use my location (reduced accuracy, one position, never tracked) | The position rounded to about a kilometre, to the owner's hub only; the device finds it itself, with no map service | Since 2026-11-06 |
| Steam, Google and Atlassian sign-in pages | Tapping Sign in (Apple's secure sign-in sheet) | What the owner types on the service's own page and the hub's return address. The sheet shares Safari's cookies with that service | Built as designed |
| Siri | A spoken request or Shortcut (App Intents) | The spoken words, processed by Siri; the result goes to the hub | Built as designed |
| Links opened only when tapped | Apple Maps with a person's address, renewal pages, Letterboxd, job postings, Confluence, links in wiki pages and replies | The link's address | Built as designed |

Steam game pictures come from the hub (`/games/art/:appid`) and outside wiki pictures load only when tapped (since 2026-11-05). `NSAllowsArbitraryLoads` is gone: plain HTTP is allowed only to a local hub and to `*.ts.net` names, whose traffic WireGuard encrypts. A device the hub says was removed deletes its key and its local copy.

## Install, update and build (run by the owner, not by the running app)

- `deploy/install.sh`: `raw.githubusercontent.com` (the script itself), `github.com` (the code, with git, checked against its commit; without git the installer stops and says how to get it), `nodejs.org` (Node and its `SHASUMS256.txt`, checked before use), `registry.npmjs.org` (packages, during `npm ci`, checked against the lock file), `github.com` again for the prebuilt `better-sqlite3` binary, and when chosen: `github.com/ollama/ollama` releases (Ollama, about 1.6 GB on Linux and 190 MB on a Mac, asked first at a terminal), `github.com/searxng/searxng` and PyPI (`pypi.org`, `files.pythonhosted.org`) for SearXNG (and, only on a machine without Python 3.10 or newer, a pinned Python from `github.com/astral-sh/python-build-standalone`, checked against its published SHA-256), and `torproject.org` (`aus1.torproject.org`, `dist.torproject.org`, `openpgpkey.torproject.org`, and `check.torproject.org` from SearXNG's start-up check) for Tor, asked first at a terminal. Before each change to the system (lingering, Tailscale Serve, opening the browser) it prints a line saying what it does. It says whether the hub's disk is encrypted. A machine with a public internet address gets a hub that listens only on itself unless `EA_LAN=1`.
- `deploy/install.ps1` (Windows): the same as `install.sh`, except that Ollama is the 1.6 GB Windows build; git, when
  the PC has none, is MinGit from `github.com/git-for-windows/git` releases; Python for SearXNG always comes from
  `github.com/astral-sh/python-build-standalone`; and Tor is checked against its published sums file only (Windows has
  no gpg to check that file's signature, which `install.sh` does). Each download is checked against its published
  SHA-256. With Tailscale chosen and missing, it downloads Tailscale's installer from `pkgs.tailscale.com` and checks it against Tailscale's published SHA-256. It also talks to the Tailscale service on the PC (`tailscale status`, `tailscale serve`) and registers the
  scheduled task `\Aeneas\Aeneas hub`, after saying so. `deploy/windows/update.ps1` reaches what `update.sh` does.
- `deploy/install-hub.sh`: the Debian or Ubuntu mirrors and `deb.nodesource.com`. `deploy/install-hub-user.sh`: `nodejs.org`.
- `deploy/litestream/install-litestream.sh`: `api.github.com` and `github.com` for the Litestream release.
- `deploy/update-hub-user.sh` and `deploy/update-hub.sh`: `registry.npmjs.org` during `npm ci`.
- `deploy/windows/build-tauri.ps1`: winget's sources (Microsoft; winget shows their terms, nothing is accepted for the owner), `crates.io` and `static.crates.io` for Rust crates, `registry.npmjs.org`. `deploy/windows/install-ollama-model.ps1`: `ollama.com/download/windows` (a link), winget for Ollama, and Ollama's registry for the model; with `-ListenOnTailnet` Ollama listens on the PC's Tailscale address only.
- `deploy/publish-ios-build.sh`: Apple's developer services for signing.
- `login.tailscale.com/admin/dns` and `litestream.io` appear in the runbook and READMEs as links.

## Addresses in the code that are never contacted

- `www.w3.org`: the SVG and XML namespace name.
- `specs.openid.net`: the OpenID protocol's name, sent to Steam as a value.
- `www.googleapis.com/auth/gmail.readonly`: the name of Gmail's read-only permission.
- `schema.tauri.app`: the schema code editors read.
- `www.irs.gov` and `www.ssa.gov`: the sources for the take-home pay numbers, cited in a comment in `hub/src/takehome.ts`.
- `github.com`: the wiki turns links to a repository's files into links on github.com; the hub fetches nothing from it.
- `api.openai.com`: the address Welcome fills in for the OpenAI choice. It is contacted only after the owner saves that choice (see the first row under Hub).

## Known gaps

1. The hub's database (`hub.sqlite`, `chats.sqlite`) is plain on the hub's disk; only work items are sealed. Backups and copies are encrypted. The installer says whether the disk is encrypted (FileVault, LUKS) and the owner decides.
2. SearXNG's Python packages come from PyPI over HTTPS without hashes to check against (pip has none for SearXNG's requirements).
3. Not verified on a running system: the exact network calls SearXNG's engines make at start on the pinned commit, whether SearXNG logs queries when an engine fails, WebView2's SmartScreen setting under Tauri, and which voices Chrome and Edge mark as on-device.
